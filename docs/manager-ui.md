# FC27 本地管理界面

界面采用原生 HTML、CSS、JavaScript，连接 Python 标准库提供的本机服务，复用现有离线管理核心。中文页面支持候选搜索和多选、详情与字段查看、离线预检、登记、模块构建、合并冲突预览、合并重编译、创建实验副本及还原。无需安装前端依赖或运行 npm 构建。

## 启动

推荐双击 `dist/FC27Manager/FC27Manager.exe`，在独立桌面窗口运行，无需安装 Python。它自动连接当前项目工作区；同一管理目录只打开一个桌面实例。窗口关闭或点击“退出管理器”时，会等待当前任务完成再停止服务。运行环境、移出项目后的工作区选择及源码构建见 [Windows EXE 说明](exe-packaging.md)。

根目录 `启动管理器.cmd` 优先运行已构建的 EXE；没有该文件时使用 Python 3.13 启动浏览器版。浏览器版需保留服务窗口，关闭网页不会停止后台任务。

也可以在项目目录运行：

```powershell
python scripts/fc27_ui.py --open
```

默认手动启动地址为 `http://127.0.0.1:8767`。端口被占用时，使用 `--port 0 --open` 自动选择；启动输出会给出实际地址。

```powershell
python scripts/fc27_ui.py --root 'local/another-manager' --port 0 --open
```

服务仅监听 `127.0.0.1`。源码界面资源来自项目 `resources/ui/`，EXE 使用包内界面资源；两者读取相同的外部管理数据。字体使用系统字体，页面没有外部脚本、字体、图片或遥测请求。

0.3.0 默认打开“玩法包”首页，普通用户无需填写 SDK、参考包或配置研究工作区。内置方案可以自动从完全匹配的本机原版准备离线副本；实际加载尚未完成，首页始终显示未启用。开发者工具折叠保留；需要扩展研究时才在“工作区设置”配置本机研究输入。见 [普通用户入口](player-entry.md)。切换管理目录时使用 `--root` 重新启动服务；页面没有游戏目标目录的写入设置。

## 页面操作

| 页面 | 操作 |
| --- | --- |
| 玩法包 | 自动识别本机游戏、核对索引版本、选择内置方案；明确展示不能启用，折叠入口可自动准备离线副本 |
| 候选库 | 搜索、多选、查看资产和字段、执行离线预检、登记完整已有候选 |
| 构建与合并 | 填写名称和唯一标识，选择全部模块或单一模块，构建并登记；勾选至少两份候选，检查冲突后合并重编译 |
| 副本与恢复 | 选择候选创建项目内实验副本，核对备份与当前文件，恢复已有副本 |
| 工作区设置 | 查看管理目录、配置路径、只读游戏来源；首次初始化工作区 |

“构建并登记”串联研究、定点编译、打包、加载副本检查和登记；“合并重编译”从原版基线生成一套共同索引。列表与详情展示登记快照；预检通过标签显示本次服务会话中检查完成的时间，不能证明稍后游戏更新后仍然兼容。共同输出路径要求重建，不代表字段冲突。

应用及恢复只操作 `local/<管理目录>/rehearsals/<副本标识>/target/ModData/`。覆盖前保存完整原始索引，恢复前再次核对日志绑定、全部备份与当前内容。文件或备份被手动改动时，任务失败并显示原因，不覆盖这些内容。副本列表只展示日志快照，点击“核对状态”才执行实际文件校验。边界、合并规则及恢复机制详见 [管理核心说明](mod-manager.md)。

## 后台任务

服务同时执行一个管理任务，另外保留核心的操作系统文件锁，防止与命令行管理器同时修改工作区。任务执行时页面继续响应，管理操作按钮暂时禁用；底部显示当前操作、经过时间、成功或失败原因及可展开的完整结果。没有使用预计百分比代替实际进度。

界面持久保存最近 50 项任务；重启后将未完成任务标为中断，不自动重试。历史预检不作为本次会话证明。底部显示实际阶段与研究资产数量；流水线报告记录每阶段耗时。登记、构建报告、备份和事务日志继续保存在磁盘。页面刷新可读取当前服务正在执行的任务。服务连接中断时页面显示提示并自动重连。

正常退出时，在服务窗口按 Ctrl+C，会停止接收请求并等待当前任务结束。直接关闭窗口或强制结束进程可能中断操作；完整事务日志产生后的副本可继续按核心规则恢复，未完成的构建目录保留供检查，不能复用原标识覆盖。

## 验证范围

全仓 185 项测试通过，其中原有 14 项界面服务测试覆盖操作参数白名单、选择范围、核心调用映射、串行任务、失败后的继续操作、读取状态响应、目录边界、本机监听、Host/Origin/会话令牌、重复 JSON 键、请求大小、静态文件白名单及 HEAD 响应。另新增 6 项 EXE 工作区与单实例测试、3 项退出与任务收尾测试。

浏览器检查覆盖桌面布局与默认窄屏布局、候选预检、勾选后冲突预览、构建表单、后台任务与页面切换、副本应用及还原。通过界面构建 `ui-role-v1` 角色执行候选：1 份资产、7 项修改、21 个变更字节。随后创建 `ui-trial-01` 副本，保存 4 份原始索引备份，应用后为 81 份文件；还原后 79 份文件与应用前基线清单完全一致。相关本机证据与截图保存在 Git 忽略的 `local/research/2026-10-08/notes/`。

Windows EXE 已完成实际 WebView2 窗口检查与封装服务构建：新增 `exe-role-v1` 候选，完成全部离线流水线，并再次核对 79 份原版元数据一致。打包环境与验证范围见 [EXE 说明](exe-packaging.md)。

界面不启动游戏，不写入游戏安装目录，不提供模组安装或游戏启动按钮。游戏加载兼容性、封装接受性与比赛效果保持未验证。
